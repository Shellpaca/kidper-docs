# README

## 目的

本セクションは、システム全体の**アーキテクチャ構造と責務の分離方針**を示すことを目的とする。  
個々の実装や技術詳細ではなく、**構造・依存関係・設計上の意図**を共有するための資料である。

設計判断・実装・運用における共通の前提を提供する。

---

## 記載内容

本セクションには、以下の内容を含む。

- アーキテクチャのレイヤー構成と依存関係
- レイヤー間のデータ受け渡しの方針
- 外部システムとの接続方法と責務分離
- 更新系・参照系における責務の分離
- システムコンテキスト図（C4: Context）
- コンテナ図（C4: Container）
- インフラ構成の全体像

これらは、図（mermaid）を用いて表現される。

---

## 記載しないこと

本セクションでは、以下の内容は扱わない。

- 各レイヤー内部のクラス設計や実装詳細
- フレームワーク固有の設定方法
- API のリクエスト・レスポンス仕様
- デプロイ手順や運用手順の詳細
- 単一機能に特化した設計判断
- ドメインルール（domainを参照）
- 業務フロー（usecaseを参照）
- API仕様（apisを参照）
- DB（tblsを参照）

これらは、それぞれ domain / api / operation / infrastructure などのセクションで扱う。

---

## 位置づけ

本セクションは、システム全体設計の**上位概念**に位置づけられる。

- domain セクションで定義された概念を前提とする
- api / usecase / infrastructure の設計判断の基盤となる
- 実装前・設計レビュー時に参照されることを想定する

詳細な設計判断の背景は、ADR を参照する。

---

## 特徴やルール

- 図は「責務」と「依存関係」を示すことを目的とする
- 図中に実装技術の詳細を書きすぎない
- 依存方向は常に明示し、循環依存を許可しない
- レイヤー構造は変更されうるが、意図は README に反映する
- アーキテクチャ変更時は、本 README を必ず見直す
