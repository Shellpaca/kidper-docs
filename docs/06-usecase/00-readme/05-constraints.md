# Constraints

制約は、「前提として縛られている条件」。判断以前に、最初から動かせない枠。

Rules と Constraints は役割が異なる

> Rules =「判断のための決まり」
> Constraints =「どうやっても越えられない制限

## 目的

本ドキュメントは、ユースケースに内在する制約条件を明示し、  
「できないこと」「制限されていること」を事前に共有することを目的とする。

後から仕様漏れや誤解が発生することを防ぐ。

## 記載内容

**業務上の制約**

- ユーザーや業務ルールに起因する制限事項

**運用上の制約**

- 実行タイミング、回数、状態などに関する制限

**前提となる制限**

- 他ユースケースや外部条件に依存する制約

---

## 記載しないこと

- システム性能やインフラ構成
- 技術的な上限値（サイズ、件数など）の実装詳細
- 一時的な運用回避策

---

## 位置づけ

- overview / rules を補足する「できる範囲の明示」
- 実装・QAフェーズでの想定外動作を防ぐための資料
- 将来の仕様拡張時に見直される前提条件の一覧

---

## 特徴やルール

- 制約は「前提条件」とは明確に区別して記載する
- 恒久的な制約と、見直し可能な制約を混同しない
- 技術的制約ではなく、業務・運用視点を優先する
- 将来的に変更される可能性がある場合は明示する
