# Rules

「どう振る舞うべきか」を決めるための判断基準。

Rules と Constraints は役割が異なる

> Rules =「判断のための決まり」
> Constraints =「どうやっても越えられない制限

## 目的

本ドキュメントは、ユースケースを成立させるための業務ルールを明文化し、  
「なぜそう振る舞うのか」「何を守る必要があるのか」を共有することを目的とする。

仕様判断の拠り所となるルールを、人が読める形で整理する。

## 記載内容

**業務ルール**

- ユースケース内で常に守られるべき制約や判断基準
- 操作や状態遷移に影響を与える前提ルール

**判断基準**

- 分岐が発生する場合の業務的な判断条件
- 正常・非正常を分ける基準

---

## 記載しないこと

- バリデーション実装の詳細
- 例外クラスやエラーコード
- フレームワークやライブラリに依存した記述

---

## 位置づけ

- overview で示された目的を、業務判断レベルで補強する資料
- state / sequence に現れる振る舞いの「理由」を説明するドキュメント
- 実装・テスト時の仕様ブレを防ぐための参照点

---

## 特徴やルール

- ルールは「〜してはいけない」「〜でなければならない」形で明確に書く
- 技術的都合ではなく、業務上の理由を優先する
- ユビキタス言語を用い、曖昧な表現を避ける
- 例外的な扱いがある場合は、その理由を明示する
