## 目的

本セクションは、ユーザーの操作とシステムの状態遷移を**時系列で理解**できるようにすることを目的とする。  
処理の流れを追いながら、**どの段階で誰が何を責務として担うか**を可視化する。

本セクションは、実装や API を理解する前段として、  
業務・画面・処理の流れを俯瞰するための資料である。

---

## 記載内容

本セクションには、以下の内容を含む。

- ユーザーの操作手順
  - 画面遷移
  - 操作の順序
- システムの状態遷移
  - idle / loading / success / error など
- 正常系の操作フロー
- 代表的な例外フロー
  - 入力ミス
  - 通信失敗
- 正常系シーケンス図
- 主要な異常系シーケンス図
- コンポーネント間の役割分担

これらは、図や時系列表現を用いて記載される。

---

## 記載しないこと

本セクションでは、以下の内容は扱わない。

- API 名や HTTP メソッド
- リクエスト・レスポンスの構造
- 実装クラスや技術選定の詳細
- パフォーマンスや最適化の話題

これらは、api / architecture / implementation に委ねる。

---

## 位置づけ

本セクションは、**ユースケース仕様の入口**に位置づけられる。

- usecase の概要を理解したあとに読むことを想定する
- 実装前の合意形成資料として利用する
- 非エンジニアを含む関係者が、処理の流れを共有するために用いる

技術的な正確性よりも、**理解しやすさと合意形成**を優先する。

---

## 特徴やルール

- 「人の操作」を起点にシーケンスを記述する
- 内部処理は責務単位でまとめ、過度に分解しない
- 正常系を主軸とし、例外系は代表例に絞る
- 状態遷移は必ず明示する
- 実装変更があった場合でも、操作フローが変わらない限りは更新不要とする
