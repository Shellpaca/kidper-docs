# シーケンス

## 目的

本セクションは、システムが提供する**業務ユースケース単位の仕様**を整理することを目的とする。  
API や内部実装ではなく、**業務の流れと完了条件**を中心に記載する。

本セクションは、人が読んで業務を理解するための**主仕様**として位置づけられる。

---

## 記載内容

本セクションには、以下の情報を含む。

- 業務ユースケースごとのディレクトリ
- 各ユースケースの概要説明
- 想定されるユーザー
- ユースケースの前提条件
- ユースケースの完了条件

各ユースケースは、1つの業務目的を単位としてまとめる。

---

## 記載しないこと

本セクションでは、以下の内容は扱わない。

- API エンドポイント単位の仕様
- リクエスト・レスポンスの詳細
- 内部クラス構造や実装手順
- 技術的な最適化やパフォーマンス調整
- フレームワークやライブラリ依存の説明

これらは、api / domain / architecture などのセクションで扱う。

---

## 位置づけ

本セクションは、システム仕様の**利用者視点の入口**に位置づけられる。

- domain で定義された概念を前提とする
- api 設計や実装の判断材料となる
- 業務要件の確認や合意形成に使用される

設計上の判断や構造的な背景は、architecture や ADR を参照する。

---

## 特徴やルール

- ユースケースは API ではなく「業務の流れ」を単位とする
- 1ユースケース = 1業務目的とする
- 各ユースケース配下には overview.md を必ず設ける
- overview.md には以下を必ず含める
  - ユースケースの目的
  - 想定ユーザー
  - 前提条件
  - 完了条件
- 技術詳細が必要な場合は、別セクションへリンクする
