# Introduction

## ドキュメントの目的

**Kidperのドキュメント**である。
このドキュメントは、本アプリの **仕様・設計判断・合意**を長期的に共有・維持するためのドキュメントである。

## 記載内容

- 要件・ユースケース・UI・ドメイン定義
- システム全体の構造と設計判断
- 仕様変更に関する判断履歴

## 記載しないこと

- 実装詳細（コード・フレームワーク・ライブラリ）
- 一時的なメモや作業ログ
- 個人のノウハウやベストプラクティス集

## ドキュメントの注意点

- 人間が理解・議論・判断するための読み物である
